# Как рассказать о проекте

«Я сделал сервис сортировки обращений. API сохраняет обращение и задание
в одной транзакции. Worker получает ID через RabbitMQ, определяет тему
и записывает результат. Если уверенность низкая, обращение остаётся оператору.
Операторские правки сохраняются отдельно и могут использоваться в обучении».

## Какие решения стоит уметь объяснить

**Почему сначала PostgreSQL, затем RabbitMQ.** Если сначала опубликовать
сообщение, а запись в БД не сохранить, worker получит несуществующее обращение.
Если просто записать и отправить без повторов, сбой между операциями потеряет
задание. Здесь запись со статусом и lease позволяет восстановить публикацию.

**Почему нужен token.** Старый worker может вернуться после того, как задание
уже забрал другой. Сравнение token перед commit защищает готовый результат.

**Зачем несколько выборок.** На fit строятся признаки и веса, calibration
нужна для температуры, validation — для выбора модели и порога. Test отвечает
на вопрос о результате после этих решений. Словарь по всему датасету тоже
может создать утечку, даже если метки test в обучение не передавать.

**Что дало сравнение.** Простая модель получила macro-F1 0.7710, модель со
словами и символами — 0.9035. Это результат на BANKING77. Доля автоматических
решений и их точность рассматриваются вместе: изменение порога меняет обе.

**Почему не учиться на всех прогнозах.** Ошибки модели стали бы её новыми
«правильными» метками. Здесь используются только явные операторские правки;
конфликты и совпадения с отложенными данными исключаются.

**Что пока ограничено.** Один английский домен и фиксированные темы,
простой фильтр неизвестных запросов, один helpdesk, локальные артефакты,
без автоматического переобучения и развёртывания.

На демонстрации: создать обращение о потерянной карте, затем короткое `my money`,
исправить второе, показать историю и экспорт. После этого запустить recovery
script и показать две попытки worker с одной зафиксированной классификацией.

Это портфолио-проект с собственным обучением и проверкой классификатора.
Его можно описывать как выполненную работу, сохраняя различие между ней
и коммерческим опытом ML.
