# Как устроен TriageDesk

## Обращение и очередь

Приём обращения — одна транзакция PostgreSQL: текст, версия модели и событие
создания записываются вместе. Само обращение в статусе pending служит
сохранённым заданием. HTTP-запрос не зависит от доступности RabbitMQ.

Dispatcher выбирает pending и просроченные задания через `FOR UPDATE SKIP LOCKED`,
назначает новый token и lease, затем публикует ID в quorum-очередь с publisher
confirms. Если публикация потеряна, PostgreSQL всё ещё хранит задание.
После lease его можно опубликовать снова.

Worker переводит queued в processing только при совпадении token. Повторное
сообщение не проходит это условие. Результат модели, конечный статус и событие
classified сохраняются в одной транзакции. После перезапуска новый token
защищает данные от старого worker, который внезапно закончил работу.

Здесь доставка сообщений допускает повторы. Гарантия проекта — одна
зафиксированная классификация обращения, даже если попыток было несколько.
После трёх неудачных попыток инференса обращение передаётся оператору с
`inference_unavailable`. Недоступность брокера не увеличивает счётчик инференса.

## Идемпотентность и версии

Ключ уникален в пределах пользователя. Advisory lock сериализует одинаковые
ключи, а hash нормализованного и замаскированного текста вместе с языком
выявляет изменение запроса. Повтор возвращает то же обращение и ту же версию
модели, даже если оператор уже включил другую.

У обращения неизменяемые текст и model_version. Активация влияет только
на новые обращения. Версия модели зарегистрирована с SHA-256 manifest;
сам manifest содержит SHA-256 словарей и весов. Уже зарегистрированную
версию нельзя перезаписать через seed.

Модель хранится в JSON и NPZ. Загружаются только словари и числовые массивы,
`allow_pickle=False`; загрузки Python-объектов из артефакта нет. Файлы входят
в образ контейнера, API загрузки моделей не предоставляет. SHA-256 проверяется
при первом открытии версии процессом, после чего используется кэш из двух
моделей. Для замены файлов нужен новый образ и новая версия.

## Ручная проверка

Клиент видит свои обращения; роль admin представляет оператора единой службы
поддержки. Это одна организация, без заявлений о multi-tenant SaaS.

Оператор может исправить автоматический ответ или ответ другого оператора.
`If-Match` проверяется после блокировки обращения. При двух параллельных
правках одна проходит, другая получает 412. Сохраняются исходный прогноз,
итоговая тема и отдельная запись каждой правки.

Экспорт отдаёт неизменяемые события review по возрастающему ID. Клиент читает
страницы через `next_after`. Скрипт обучения выбирает последнюю правку
каждого обращения, проверяет язык и класс, убирает конфликты, повторы и
пересечения с отложенными выборками. Автоматические ответы сами по себе
обучающими метками не становятся.

## Где выполняется ML

Вызов модели идёт в thread pool worker, поэтому heartbeat и обработка
соединения с RabbitMQ продолжаются. Prefetch равен 1. Словарь и IDF обучены
только на train; калибровка, выбор порога и оценка разделены.

Отдел выбирается по явным правилам из темы. Это бизнес-правила маршрутизации,
а не вторая обученная модель. Они находятся в `department()` и покрывают
карты, платежи, переводы, пополнения, операции с наличными, безопасность,
верификацию и обслуживание аккаунта.

## Данные и эксплуатация

Перед сохранением маскируются email и длинные группы цифр. Тексты не пишутся
в логи и сообщения RabbitMQ. Это простая защита от случайного сохранения
контактов и номеров, а не полная обезличивающая система: имена, адреса и
другие персональные данные могут остаться в тексте.

В локальной версии нет автоматической очистки обращений, квот пользователя,
лимита частоты запросов и распределённого файлового хранилища моделей.
Для внешнего развёртывания нужны сроки хранения, резервное копирование,
отдельные секреты, TLS и ограничение входящего потока. Фиксированный lease
также нужно пересмотреть для моделей с долгим инференсом.

Источники: [RabbitMQ reliability](https://www.rabbitmq.com/docs/reliability),
[PostgreSQL SELECT и SKIP LOCKED](https://www.postgresql.org/docs/17/sql-select.html),
[scikit-learn: работа с текстом](https://scikit-learn.org/stable/modules/feature_extraction.html).
